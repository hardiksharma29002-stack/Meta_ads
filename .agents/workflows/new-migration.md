# Workflow: Creating and Applying Database Migrations

## Objective
Implement schema alterations safely using SQLAlchemy 2.0 and Alembic, guaranteeing zero downtime and non-destructive rollbacks.

## Principles: Expand-Migrate-Contract
1. **Never drop columns or tables in a single release step.**
2. **Phase 1 (Expand):** Add new nullable columns or tables. Update backend models to write to both old and new columns.
3. **Phase 2 (Migrate):** Backfill data from old structures to new structures.
4. **Phase 3 (Contract):** Switch read paths to new structures, deprecate old columns, and drop old structures in a subsequent deployment.

## Execution Steps

### 1. Update SQLAlchemy Declarative Models
1. Modify or add ORM model definitions under `backend/app/db/models/`.
2. Ensure new columns specify appropriate defaults, nullability, and indexing strategies.
3. Add inline docstrings explaining field provenance and retention intent.

### 2. Generate Alembic Revision
Run the migration generator inside the container environment:
```bash
docker compose exec api alembic revision --autogenerate -m "<descriptive_slug>"
```
Review the generated file under `backend/app/db/migrations/versions/`.

### 3. Review Generated Migration Script
Verify the following safety checks in the generated script:
- Autogenerated statements do not unexpectedly drop unrelated tables or indexes.
- All new foreign keys include appropriate `ON DELETE` clauses (`CASCADE` or `RESTRICT`).
- Complex transformations include explicit `downgrade()` procedures.
- Trigram indexes use `gin (col gin_trgm_ops)`.

### 4. Execute Migration in Local Test Environment
Apply and roll back the revision against a clean test database:
```bash
# Upgrade to head
docker compose exec api alembic upgrade head

# Rollback one revision to test downgrade integrity
docker compose exec api alembic downgrade -1

# Re-apply to head
docker compose exec api alembic upgrade head
```

### 5. Update Documentation & Data Model Spec
Update `docs/DATA_MODEL.md` to reflect the updated schema, ER diagram, and retention implications.
